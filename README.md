# PPIP: Placement Preparation Intelligence Platform

PlacementPrep is an iOS, iPadOS and Mac Catalyst app for campus placement preparation. It has topic-wise quizzes, company-tagged DSA question lists, AI mock interviews with voice input, and XP and streak tracking.

## Repository layout

| Path | What it is |
| --- | --- |
| `frontend/` | SwiftUI app (iOS 17+, no third-party dependencies). The Xcode project is generated from `project.yml` by [XcodeGen](https://github.com/yonaskolb/XcodeGen). |
| `backend/` | FastAPI service: auth (JWT, email OTP, Google/GitHub sign-in), mock interviews (Groq/Gemini, Whisper transcription) and content routes. |
| `database/` | SQLModel table models and the engine/session, shared by the backend. |
| `Dockerfile`, `fly.toml` | Container image and Fly.io config for the backend. |

## Running the backend

Requires Python 3.10+.

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # then set JWT_SECRET_KEY and at least one of GROQ_API_KEY / GEMINI_API_KEY
uvicorn app.main:app --reload --port 8000
```

API docs are served at `http://localhost:8000/docs`. Google and GitHub sign-in stay disabled until their client ID and secret are set in `.env`.

## Running the app

```bash
cd frontend
xcodegen generate            # re-run after adding, removing or renaming files
open PlacementPrep.xcodeproj
```

The app talks to `http://localhost:8000` by default. To point it somewhere else, set the `PPBackendURL` user default.

### Content scripts

Quiz and company content ships in the app bundle and is regenerated by scripts in `frontend/Scripts/`:

```bash
python3 Scripts/validate-quizzes.py      # run after editing any quiz JSON
python3 Scripts/shuffle-quiz-answers.py  # re-deal a quiz's answer key if validation flags a pattern
./Scripts/fetch-company-csvs.sh          # refresh Resources/Companies/*.csv
python3 Scripts/fetch-company-logos.py   # refresh Resources/Logos/*.png
```

## Deploying

The backend deploys to Fly.io from the repo root, because the image needs both `backend/` and `database/`. Secrets such as `JWT_SECRET_KEY` and the API keys go in `fly secrets set`, never in `fly.toml`.
